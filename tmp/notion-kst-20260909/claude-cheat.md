## 프롬프트 & Fable 5.1 대화법 (01–25)
	**01. 볼드 금지 룰 지우기** — 5.1은 볼드·목록을 덜 쓰니 옛 "볼드 쓰지 마"는 역효과다
	어디서 켜나: `Settings → Instructions for Claude (또는 프로젝트 지시문)에서 '볼드 쓰지 마' 류 규칙 삭제`
	```plain text
강조는 핵심 1~2곳만, 목록은 3개 이상 나열될 때만 써줘.
[요청]
	```
	**02. "꾸민 문장 빼줘"** — 5.1은 문장이 길고 빽빽해서 이 한 줄이면 확 가벼워진다
	```plain text
Please remove all mannered prose.
꾸민 표현과 군더더기 문장은 빼고 담백하게 써줘.
[요청]
	```
	**03. "나는 실시간으로 안 봐"** — 이 한 문장이 5.1의 멈춤·허락 묻기를 가장 줄인다
	```plain text
나는 실시간으로 보고 있지 않아.
되돌릴 수 있는 작업은 묻지 말고 진행하고, 삭제·발송처럼 되돌릴 수 없는 것만 멈추고 확인받아.
일: [요청]
	```
	**04. 진행 보고 시키기** — Cowork 같은 긴 작업엔 시작·중간·끝 보고를 시킨다
	```plain text
시작 전에 뭘 할지 한 줄, 작업 중엔 짧은 진행 상황, 끝나면 이 답만 읽어도 되는 요약을 남겨줘.
일: [긴 작업 요청]
	```
	**05. 판단만 원하면 말해두기** — "고치지 말고 평가만"이 없으면 손을 댄다
	```plain text
고치지 말고 평가만 해줘. 문제점과 이유를 목록으로. 수정안은 내가 요청하면 그때.
"""
[자료]
"""
	```
	**06. 범위 밖은 보고만** — 다른 문제를 발견해도 고치지 말고 목록으로 남기게 한다
	```plain text
요청한 것만 고쳐. 작업 중 다른 문제를 발견하면 고치지 말고 맨 아래 '후속 확인' 목록으로만 적어줘.
요청: [내용]
	```
	**07. 부분 수정 지시** — "결과 같으면 통째 재작성 말고 그 부분만", 출력 토큰이 준다
	```plain text
결과가 같다면 파일을 통째로 다시 쓰지 말고 필요한 부분만 고쳐줘. 바뀐 부분만 보여줘.
요청: [내용]
	```
	**08. 그 턴만 High** — 검색 안 하고 기억으로 답하면 그 질문만 Effort 를 올린다
	어디서 켜나: `전송 버튼 옆 모델명 → Effort → High (이 질문만, 답 받고 다시 낮추기)`
	```plain text
이 질문은 기억으로 답하지 말고 검색해서 최신 기준으로 답해.
질문: [내용]
	```
	**09. 이름은 검색시키기** — "아는 이름도 최신 상태는 검색해"를 미리 적는다
	```plain text
아는 이름이어도 최신 상태는 검색해서 확인해. 내가 쓴 표기 그대로 검색해.
대상: [회사·제품·인물 이름]
	```
	**10. 인용 예시 1개** — 인용 표시 없이 원문을 옮기니 올바른 예를 1개 준다
	```plain text
출처 문장을 쓸 때는 이렇게 표시해:
예) 공식 문서는 "원문 그대로"라고 밝혔다 (출처: 문서명)
인용 표시 없이 원문을 그대로 옮기지 마.
요청: [내용]
	```
	**11. 5.1 글은 상투구가 줄었다** — 옛 "AI 티 빼줘" 지시는 빼고 다시 본다
	어디서 켜나: `Instructions for Claude 에서 'AI 티 나는 표현 금지' 류 규칙 삭제 후 결과를 먼저 본다`
	```plain text
(규칙 없이) [요청]만 보내고, 부족하면 그때 한 줄만 추가
	```
	**12. 5.1은 원인을 고친다** — 증상만 막지 않으니 오래 묵은 문제를 맡겨본다
	```plain text
증상만 막지 말고 근본 원인을 찾아서 고쳐줘.
원인 → 왜 그런지 → 고친 것 순서로 보고해.
문제: [설명]
	```
	**13. 골든룰** — 동료가 읽고 헷갈리면 Claude 도 헷갈린다
	```plain text
(보내기 전 자가 점검)
이 프롬프트를 처음 보는 동료가 읽어도 무엇을·왜·어떤 형식으로 해야 하는지 바로 알 수 있나?
하나라도 '아니오'면 그 항목을 한 줄 추가
	```
	**14. 목표 1문장 먼저** — 첫 줄에 "원하는 결과는 OOO"부터 적으면 답이 산으로 안 간다
	```plain text
원하는 결과: [한 문장으로]
그다음에 요청: [무엇을 해줘]
	```
	**15. 맥락 한 줄 붙이기** — 누가·왜·어디에 쓰는지만 적어도 답의 결이 달라진다
	```plain text
맥락: 이 결과는 [누가] [왜] [어디에] 쓸 겁니다.
요청: [무엇을 해줘]
	```
	**16. 역할 한 문장** — "너는 10년 차 OO야" 한 줄로도 관점이 고정된다
	```plain text
너는 [10년 차 마케팅 담당자]야. 그 관점에서 [무엇을] 해줘.
	```
	**17. 금지 대신 지시** — "마크다운 쓰지 마" 말고 "문단으로 써"가 먹힌다
	```plain text
(하지 말 것 대신 할 것으로)
마크다운 없이 매끄러운 문단으로 써줘.
표 대신 문장으로 비교해줘.
요청: [내용]
	```
	**18. 서두 없이** — "서론 없이 바로 답해"가 공식 문장, 답이 본론부터 짧게 온다
	```plain text
서론 없이 바로 답해. 'Here is…', '~에 따르면' 같은 도입 문장 없이 첫 줄부터 본론.
요청: [내용]
	```
	**19. 내 글 모양 = 답 모양** — 프롬프트에 마크다운을 안 쓰면 답도 마크다운이 준다
	```plain text
(프롬프트 자체를 마크다운 없이 평문으로 쓴다 — 굵게·목록·# 을 쓰지 않으면 답도 그렇게 온다)
요청: [평문으로 쓴 내용]
	```
	**20. 순서 중요하면 번호로** — 빠지면 안 되는 단계는 1·2·3 으로 적는다
	```plain text
아래 순서를 빠짐없이 지켜서 해줘.
1. [단계]
2. [단계]
3. [단계]
각 단계가 끝나면 번호를 적고 다음으로 넘어가.
	```
	**21. 좋은 예시 1개** — \<example\>로 감싼 샘플 하나면 결과가 그쪽으로 정렬된다
	```plain text
<example>
[좋은 예시 붙여넣기]
</example>
위 예시와 같은 톤·형식으로 [요청]
	```
	**22. 태그로 감싸기** — \<지시\> \<자료\> \<입력\>처럼 종류별로 감싸면 오해가 준다
	```plain text
<instructions>
[무엇을 해줘]
</instructions>
<context>
[배경·조건]
</context>
<input>
[자료 붙여넣기]
</input>
	```
	**23. 출력 형식 고정** — 표·목록·문단 중 하나로 잠그면 다시 손볼 일이 준다
	```plain text
출력 형식: [표 / 번호 목록 / 문단] 하나로만.
표라면 열 이름: [열1, 열2, 열3]
요청: [내용]
	```
	**24. 단계 지시 대신 목표** — "꼼꼼히 생각해" 한 줄이 손으로 짠 단계 계획보다 낫다
	```plain text
목표: [무엇을 달성]
제약: [조건]
꼼꼼히 생각해서 가장 좋은 방법으로 해줘. 단계는 네가 정해.
	```
	**25. 검증 지시는 모델 따라** — "끝내기 전에 검증해"는 통하지만 Opus 5 엔 역효과다
	```plain text
(Fable·Sonnet 계열) 끝내기 전에 [기준]에 맞는지 스스로 검증하고, 고친 곳을 맨 아래 적어줘.
(Opus 5) 이 문장은 빼기 — 스스로 검증하는 모델이라 넣으면 과잉 검증
	```
## 프로젝트·메모리·스킬 (26–50)
	**26. 자료는 프로젝트에** — 올린 파일은 캐시돼 다시 쓸 때 한도에 안 잡힌다
	어디서 켜나: `사이드바 Projects → 프로젝트 열기 → Project knowledge → 파일 추가`
	```plain text
프로젝트 지식의 [파일 이름] 기준으로 [요청]
	```
	**27. 새 채팅엔 캐시가 없다** — 같은 자료를 다시 붙이면 처음부터 다시 처리된다
	어디서 켜나: `(원리) 자주 쓰는 자료는 채팅에 붙이지 말고 프로젝트 지식에 한 번만`
	```plain text
프로젝트에 올린 [파일] 참고해서 [요청]
	```
	**28. 프로젝트 만들기** — 사이드바 Projects → New, 파일·규칙·대화가 한곳에 모인다
	어디서 켜나: `사이드바 Projects → + New Project`
	```plain text
이름: [ ]
지시문: [항상 지킬 것 3줄]
파일: [용어사전 / 스타일 가이드 / 자주 쓰는 자료]
	```
	**29. 프로젝트 지시문은 짧게** — 항상 지킬 것만 넣고 작업별 지시는 채팅에 쓴다
	```plain text
(프로젝트 지시문 — 이 정도면 충분)
이 프로젝트는 [무엇] 작업용.
항상: [톤], [형식], [금지 1개].
참고 파일이 있으면 그걸 우선.
(작업별 지시는 채팅에서)
	```
	**30. 안 쓰는 파일 정리** — 지금 안 쓰는 자료는 빼야 컨텍스트를 덜 차지한다
	어디서 켜나: `프로젝트 → Project knowledge → 안 쓰는 파일 옆 삭제`
	**31. 용어사전 파일 1개** — 회사 용어·금지어를 파일로 두면 매번 설명이 필요 없다
	```plain text
(파일 '용어사전.txt' 로 저장해 프로젝트에 올리기)
[우리 표기] = [설명] (다른 표기 쓰지 말 것: [ ])
[금지어] → 대신 [대체어]
[고객 호칭] = [ ]
	```
	**32. 스타일 가이드 파일** — 말투·형식 예시를 올려두면 결과 톤이 흔들리지 않는다
	```plain text
(파일 '스타일가이드.txt' 로 저장해 프로젝트에 올리기)
말투: [존댓말 / 반말], 문장 길이: [짧게]
제목 형식: [예시]
좋은 예:
"""
[우리 톤 샘플]
"""
	```
	**33. 프로젝트 대화끼리 안 섞인다** — 공유하려면 지식 파일에 넣어야 한다
	어디서 켜나: `프로젝트 안 대화끼리는 서로 모름 → 공유할 결론은 Project knowledge 에 파일로`
	```plain text
이 대화에서 정한 결론을 프로젝트 지식에 넣을 문서로 정리해줘. 제목 + 핵심 5줄.
	```
	**34. 대화를 프로젝트로** — 채팅 이름 옆 ▾ → Add to project 로 옮긴다
	어디서 켜나: `채팅 이름 옆 ▾ → Add to project`
	**35. 자료 많으면 RAG 자동** — 지식이 한도에 가까우면 필요한 부분만 찾아 읽는다
	어디서 켜나: `자동 — 프로젝트 지식이 컨텍스트 한도 근처면 RAG 모드로 전환`
	```plain text
프로젝트 지식에서 [주제] 관련 부분만 찾아서 답해
	```
	**36. 계정 지시문** — Settings 의 Instructions 에 쓰면 모든 대화에 적용된다
	어디서 켜나: `왼쪽 아래 이니셜 → Settings → Instructions for Claude`
	```plain text
(아래 템플릿 ⑤ 붙여넣기)
	```
	**37. Cowork 전역 지시문** — Settings \> Cowork 에 쓰면 전 작업 적용
	어디서 켜나: `Settings > Cowork → Global instructions → Edit`
	```plain text
파일을 만들면 항상 [폴더]에 저장. 삭제 전엔 반드시 확인. 결과는 요약 3줄로 보고.
	```
	**38. 메모리 켜기** — Settings \> Memory 에서 켜면 취향·업무를 기억해 간다
	어디서 켜나: `Settings > Memory → Generate memory from chats ON`
	**39. "기억해" 한마디** — 채팅에서 "이거 기억해" 하면 바로 저장된다
	```plain text
이거 기억해: 나는 [직업], 주로 [업무]를 하고, 답은 [선호 형식]으로 받는 걸 좋아해.
	```
	**40. 메모리는 채팅에서 고친다** — "이건 잊어"라고 하면 다음 대화부터 반영된다
	```plain text
[옛 정보]는 이제 잊어. 앞으로는 [새 정보]로 기억해.
	```
	**41. 메모리 항목 정리** — Topics 목록에서 낡은 기억을 개별 수정·삭제한다
	어디서 켜나: `Settings > Memory → Topics → 항목 클릭 → 수정·삭제`
	**42. 민감 주제 토글** — 건강·신념은 Memory 의 민감 주제 옵션을 켜야 저장된다
	어디서 켜나: `Settings > Memory → Include sensitive topics in memory ON`
	**43. 메모리 가져오기** — Memory 설정의 Start import 로 기억을 옮겨온다
	어디서 켜나: `Settings > Memory → Start import`
	```plain text
(정리해 둔 '나에 대해' 텍스트를 붙여넣고) 이걸 내 메모리로 저장해줘.
	```
	**44. 과거 대화 검색** — "이전 대화 찾아서 참고해줘"면 같은 설명을 반복 안 한다
	```plain text
이전 대화에서 [주제] 관련 내용을 찾아서 참고한 뒤 [요청]
	```
	**45. "아까 말한 대로"** — 다시 붙여넣지 말고 참조만 하면 메시지가 짧아진다
	```plain text
(같은 대화 안에서)
아까 말한 [조건] 그대로 적용해서 [요청]
	```
	**46. 시크릿 채팅** — 오른쪽 위 유령 아이콘, 메모리에 안 남고 닫으면 다시 못 연다
	어디서 켜나: `새 채팅 → 오른쪽 위 유령 아이콘 (프로젝트 안에서는 안 뜸, 닫으면 다시 못 엶)`
	**47. 내장 스킬** — Excel·Word·PPT·PDF 스킬은 자동 발동이라 부를 필요 없다
	```plain text
이 자료로 [엑셀 / 워드 / PPT / PDF] 파일 만들어줘.
구성: [시트·장·페이지 구성]
형식: [ ]
	```
	**48. 스킬 만들기** — Customize \> Skills 에 내 절차를 ZIP 으로 올린다

#### 2. 매일 반복하는 일을 AI에게 넘기는 자동화 세팅

#### 3. AI로 만드는 수익 구조
AI로 업무 시간을 줄이고 판매 채널을 세운 실제 사례를 공유합니다. 무엇을 팔지보다 어떻게 빨리 만들어 내놓는지가 핵심입니다.
